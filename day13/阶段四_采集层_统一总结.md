## 零、★★★ 网络地基(最重要,新对话必读)

**这台公司机的出网拓扑:**
```
公司电脑(本身不能直连外网)
  ├─[WireGuard 隧道] → 组长配的出口 → 公司允许的互联网
  └─[Clash Verge 本地代理 127.0.0.1:7897] → 翻墙节点 → 墙外
```

- **没有"裸直连互联网"这条路**。绕过一切 = 死路(WinError 10054 网关重置)。

**采集层出网姿势(钉死):**

2. 脚本里 **import 网络库之前**,显式设 `os.environ["HTTP_PROXY"/"HTTPS_PROXY"]="http://127.0.0.1:7897"`(已封装进 `net.py`)。
3. **不要用 `trust_env=False`**——那是阶段三 DeepSeek **直连**的姿势;雅虎/东财相反,**必须走代理**。

**★ 核心认知:同一台机器,不同目标 host,出网策略可能相反。** DeepSeek 直连、雅虎走代理,两套并存。

## 一、akshare 抓 A 股股价 + 复权三态(★回测引擎命门)

**接口**:`ak.stock_zh_a_hist(symbol, period, start_date, end_date, adjust)`。练手:茅台 `600519` 2024 全年 → 242 行(真实交易日数,非 365/250)、12 列、首尾日期正确。

**真实脏数据信号:**
- 名字字段不稳:返回 `XD贵州茅`(XD=除息),**公司名不能当唯一键**(影响知识图谱匹配)。
- `日期` 列是 **object(字符串)** → 阶段五要 `pd.to_datetime`(时间轴对齐的前提)。
- 字段顺序反直觉:**开/收/高/低**(不是开/高/低/收)。
- **HTTP 200 ≠ 业务成功**:东财响应里还有自己的 `rc:0` 业务码,两层都看。

**复权三态(茅台 2024-01-02 收盘实测):**
| adjust | 含义 | 锚点 | 实测值 |
|---|---|---|---|
| `""` | 不复权 | 无锚,真实成交价 | 1685.01 |
| `"qfq"` | 前复权 | 锚在**今天** | 1550.67(被压低) |
| `"hfq"` | 后复权 | 锚在**上市首日** | 9397.44(累加分红) |

**★ 前视偏差铁律(面试标准答案):**
- 前复权 = 用**未来**的除权除息信息改写**过去**的价格 → 历史某天的前复权价当天根本不存在。
- 回测决策喂前复权价 = 历史的你偷看未来分红 = **前视偏差(look-ahead bias)**,回测虚高、实盘崩。
- 更阴:前复权数据**每天都在变**(又分红就重算),昨天的回测结论今天复现不出。
- **回测引擎:决策/算信号用不复权或后复权(锚在过去、值稳定);前复权只配画图给人看。**
- 野怪again:同 silent failure——前复权回测不报错,但结论是假的。

**港股野怪预警**:小米用 `ak.stock_hk_hist`,**不是** A 股的 `stock_zh_a_hist`,接口不同,届时单独处理。

## 二、tenacity 重试(横切关注点 → 装饰器)

**Java 类比**:Spring Retry `@Retryable` / AOP 切面(同阶段三 instructor 的哲学)。

**重试三要素:**
- `stop=stop_after_attempt(5)` —— 试几次
- `wait=wait_exponential(multiplier=1, min=2, max=30)` —— **指数退避**,封顶 30s
- `retry=retry_if_exception_type((RequestException, ValueError))` —— **异常筛子**:只对网络错+空数据重试;`KeyError` 等代码 bug **立刻炸不重试**(裸 `except Exception` 做不到,会把 bug 伪装成网络抖动)
- `before_sleep=before_sleep_log(...)` —— 重试可观测

**silent failure 自守**:`if data is None or data.empty: raise ValueError`——空数据是业务概念,框架不懂,必须自己判。

## 三、net.py 公共模块(工程化分层)

```
net.py (基础设施层)
  ├─ 代理钉死(模块级副作用,import 即生效)
  └─ with_retry(max_attempts=5) 工厂 → 返回配好的 @retry 装饰器
业务脚本 (业务层)
  └─ import net(第一行) → @with_retry() → 调接口 + if empty 业务检查
```
**★ 设计铁律:**
- 代理设置写成 **net.py 模块顶层语句**(不是函数!),靠"import 即执行"保证早于任何网络库初始化。
- `import net` 必须在 `import akshare/feedparser/requests` **之前**。
- 业务级有效性检查(`if data.empty`)留在业务函数,不抽进通用层。
- Java 类比:net.py = common/infrastructure 包(HttpClientConfig/RetryTemplate)。

## 四、★ 代理仗完整诊断链(面试硬货)

**报错形态会变,按"卡在哪一层"读:**
1. `Unable to connect to proxy` / `RemoteDisconnected` → 卡在连本地代理 = **Clash 没在正常服务**。
2. `WinError 10054 远程主机强迫关闭`(TLS 握手)→ 摘代理走**直连被网关重置**(证明不能裸直连)。
3. `UNEXPECTED_EOF_WHILE_READING` → 走了代理但**节点扛不住大包**(台湾"5x倍率"节点)→ 换香港原生IP。
4. akshare 报 `Unable to connect to proxy` 但裸 requests 同时能通 → **akshare 内部 Session 在 import 时把代理"焊死"成空**(`proxy_debug.py` 实测 akshare Session.proxies={})。

**根因(★★ 早绑定):第三方库在 import 时固化配置,环境相关设置必须赶在 import 之前。** Java 类比:Spring bean 启动注入 `@Value`,之后改 `System.setProperty` 不认。

**诊断方法论:**
- `net_check.py`(直敲底层 API 小请求)= **网络体温计**。一报网络错先跑它:通了=代码/参数问题,不通=Clash 问题。把网络层和代码层切开,不靠猜。
- 故障注入:代理改错端口(7899)可稳定复现失败,验证重试逻辑。

## 六、feedparser 抓新闻(结构化 → 非结构化的质变)

**Java 类比**:feedparser ≈ 超宽容的 Jackson/JAXB,各种方言(RSS/Atom)反序列化成同一对象模型,字段名归一。

**数据结构**:`d.bozo`(0/1 哨兵)、`d.bozo_exception`、`d.status`、`d.feed`、`d.entries`。
**字段映射野怪**:`<description>`→`entry.summary`;`<pubDate>`→`entry.published` + 附赠 `entry.published_parsed`(`time.struct_time`)。逐 entry 用 `.get()` 不用 `e.title`(缺字段返回 None 而非 AttributeError)。

**★ bozo = "200≠业务成功"新马甲**:feedparser.parse() 几乎不抛异常,坏 feed/断网/404 都默默返回对象,错误塞进 `.bozo`。**自守三件套**:查 `.bozo` + `.status` + `len(.entries)`。

### ★★ 早绑定 vs 晚绑定:为什么 feedparser 没重演代理仗
- **akshare = 早绑定**:import 即 new Session,proxies 固化,之后改 env 不认。
- **feedparser = 晚绑定**:用 urllib,每次 parse 内部 `build_opener()`,默认 ProxyHandler **调用那刻现读 `getproxies()`(env)** → net.py 设的 `HTTP_PROXY` 被现场读到 → 生效。
- 一句话:**akshare import 时固化代理,feedparser 调用时现读代理。** 同是库自抓取,一个不吃 env、一个吃。

### ★ 网络层 / 解析层切开(net_check 方法论延续)
```python
@net.with_retry()
def fetch_feed_bytes(url):
    resp = requests.get(url, headers=HEADERS, timeout=10)
    resp.raise_for_status()            # 非2xx抛HTTPError ⊂ RequestException → 落筛子重试
    return resp.content                # ★ 字节,不是 text
d = feedparser.parse(raw)              # 纯解析
```
**唯一新认知点 `return resp.content`(字节)而非 `resp.text`(字符串)**:feed 编码声明在 XML 头;给 text → requests 已用它猜的编码解码(中文常错→乱码);给 content → feedparser 用自带的、看得懂声明的检测去解。**编码预防针。**

### ★ 空数据自守该放哪一层 —— 看数据语义,不抄模板
- **股价(akshare)**:永远有历史价,空≈服务端抽风 → **该重试**(放重试圈内)。
- **新闻(feed)**:冷门标的**可能真没新闻**,空是合法状态 → **该快速失败**(放圈外)。
- 铁律:"空数据要不要进重试圈"看数据语义。要知道自己为什么这么放。

### ★★ 源列表底盘 + 两层容错
| | 重试圈(with_retry 异常筛子) | 批处理圈(for 的 except Exception) |
|---|---|---|
| 抓法 | **窄抓** | **宽抓** |
| 目标 | 别把 bug 当网络抖动重试 | 别让一个源杀死整批 |
| 护身符 | KeyError 立刻炸 | `type(ex).__name__` 让 bug 日志现形 |

**宽抓 + 记类型 ≠ 吞异常。** Java 类比:Spring Batch fault-tolerant step(skip 坏记录+记 skip 数)。开发期想看 traceback 可临时注释 except 裸跑。
**provenance**:每条挂 `source`,为下游去重/知识图谱/评分融合(多源印证=强信号)埋桩。

### ★ 跨源重复坐实 → 两套去重动机
3 源 × 20 = **60 → 唯一 link 仅 45**。同一篇大盘横扫稿 link 字节级相同,挂三只 feed 下 → **hash 去重那一半**;不同媒体同事件 link 不同但正文相似 → **pymilvus 向量去重那一半**。两套动机一跑撞出。

### 故障注入(改坏域名)三发现
1. **`UNEXPECTED_EOF_WHILE_READING` 同形不同因**:代理仗里是节点掐大包,这次是域名不存在/代理连不上 → SSL 握手 EOF。**同形不同因**,按层读不照文本对号。
2. **`RetryError` 套娃**:tenacity 耗尽抛 `RetryError`,原始 `SSLError` 被裹里面,`except SSLError` 抓不到,需 `ex.last_attempt.exception()` 剥。(Java 类比:`ExecutionException.getCause()`。)
3. **30s 串行拖累**:单死源 2+2+4+8 退避实测十几秒,源一多串行累加拖死整批。

### 数据质量信号
前几条全是《全日速報》《港股》大盘速报,只顺带提小米 → **按代码订阅 ≠ 专属新闻**。采集层**先采全,后降噪**(降噪是下游 LLM 抽取的活)。

## 七、简体编码仗(★ 纠正前述假设)

**★ 纠正**:原始交接/旧记忆里"新浪 RSS = GBK"是 **2013 年的化石**。本次实测:
- 新浪整站 RSS **已迁 UTF-8**(`resp.encoding=ISO-8859-1`、`apparent=utf-8`、声明 `encoding="utf-8"`)。
- 且新浪财经 RSS 整批 **2018 年起停更**(`hkstock.xml` 频道结尾 pubDate 2018、0 个 item)= **空源**。
- 证券之星整站是 GBK 但 `/rss/` 入口下线。
- **结论:简体 GBK RSS 生态在 2026 基本死绝。** 现代解法 = **RSSHub**(雪球/财联社/智通财经港股,UTF-8)。

**★ 编码体检台的真价值**(本站最该记住的):它没让你抱着"新浪=GBK"的死假设撞墙,而是当场摊出真相(utf-8)。**真实世界源什么编码都有、还会变,你要的是"每源运行时现场体检"的肌肉,不是死口诀。**
- `resp.content` vs `resp.text` 分叉,本地用 `脨隆脙脳...`(latin1 错解 GBK)花屏演死过。
- **更阴**:错解时 `d.encoding` 还报 gb18030——**连 encoding 字段都在骗你**,因为坑发生在 feedparser 拿到数据**之前**。

**第三种采集层状态**:除"网络炸/解析炸",还有**空源**(XML 合法、bozo=False、0 个 item)。`if not items: continue` 正为此建。

## 八、BeautifulSoup 正文抓取(信号 vs 噪声)

**钩子兑现**:feed 的 summary 是截断预览(结尾断在半句),要全文得顺 link 抓网页解析正文。
**Java 类比**:BeautifulSoup = 门面 API(像 SLF4J),lxml = 后端实现(像 Logback)→ `BeautifulSoup(html, "lxml")`。

**★ 信号 vs 噪声(正文抽取命门)**:实测雅虎页 **493221 字节 → 整页 get_text() 仅 3182 可见字**,开头全是 `跳至導覽/雅虎香港財經/新聞/財經...` 导航垃圾。**裸 get_text 不可用**,真本事是定位正文容器。正文实在 `<div class="bodyItems-wrapper">`(1109 字)。

**★ 容器从真实输出挖,不背口诀**:我赌 `caas-body` **翻车**,真值 `bodyItems-wrapper`(诊断脚本按最长 `<p>` 反查父容器挖出)。**选择器是采集层最易腐、最不能背口诀的东西**——这是"discover-from-output"方法论第一次救场(GBK 是第二次)。

**HTML 编码野怪 again**:HTML 声明在 `<meta charset>`(不是 XML 头)。同纪律:`BeautifulSoup(resp.content, "lxml")` 字节进,BS 内置检测(实测 `original_encoding=utf-8`)。

**双层 None 自守:**
```python
node = soup.find("div", class_="bodyItems-wrapper")
if node is None: return None                       # 自守①:扑空,防 None.get_text() 崩
text = node.get_text(separator="\n", strip=True)
if not text or len(text) < 50: return None         # 自守②:语义级,防空壳/占位句
```
- **silent failure 地雷**:页面埋着隐藏 `<div class="no-data">抱歉發生錯誤</div>` 占位。若选择器扑空又图省事"随便抓个 div 兜底",可能抓到这句当正文——类型对、语义全错(同 `company='央行'` 族)。自守②专治。
- 两道都 `return None` 而非抛:批处理里一篇失败=跳过这篇,None 是好传递的失败信号。

## 九、trafilatura 通用抽取 + 架构判据

**通用抽取活法**:不用任何选择器,靠"文字密度、链接密度、标签结构"启发式自动判正文。`trafilatura.extract(raw_bytes)` 一函数吃多站。

| | 字数 | 选择器 | 元数据 |
|---|---|---|---|
| A 站点专属(bodyItems-wrapper) | 1109 | 需手挖,脆 | 无 |
| B 通用(trafilatura) | **1109(一字不差)** | **零** | **白嫖标题/日期2026-06-26/作者AASTOCKS** |

- B 零选择器追平 A,且免维护 + 白嫖元数据。

**★★ 架构判据(锁进笔记):**

## 十、整合 collect.py(采集层闭环)

**散装脚本 → 一条流水线**,产出可喂下游的"成品记录"。整合逼出两个设计决策:
1. **去重前置**:先按 link 去重(set)再抓正文——否则同一 link 抓三遍正文 = 三倍 HTTP。既省请求,又提前用上 hash 去重。
2. **MVP 限流 `MAX_FETCH=5`**:45 唯一链接串行抓要几十秒(碰死链叠 30s 退避),先限 5 条验流水线,跑通再放开。并发是优化项。

**成品记录结构**(实测 5 条全过、0 失败):`{source, title, link, published, author, body, body_len}`——一条能直接喂 LLM 的料。

**★ 信号 vs 噪声全流水线实锤(→ LLM 抽取层动机)**:5 条成品里 **4 条是港股大盘横扫稿、仅 1 条(小米回購)是真小米信号**。采集层机制完美、正文干净,但噪声占多数——**"从大盘噪声里拣出影响买卖判断的小米信号",正是下游 LLM 抽取层存在的全部理由**。采集层为下一层备好了最理想输入,也把下一层要解决的问题具体地交到手上。流水线首尾呼应,打通。

## 十一、贯穿阶段四的铁律 / 认知(浓缩)

1. **silent failure 是反复出现的野怪**:akshare 空数据 / feed bozo / None 正文 / 语义级假正文(占位句、`company='央行'`)/ 编码字段骗人。永远**核输出值,不只看报不报错**。
2. **异常处理:同写法、不同层、不同判决**——窄抓(重试圈,别把 bug 当抖动)vs 宽抓(批处理圈,别让一源杀全批)。宽度看数据语义,不看代码结构。
3. **早绑定 vs 晚绑定**:第三方库 import 时固化的配置(akshare 代理),环境相关设置必须赶在 import 前。
4. **不背口诀,从真实输出挖**:`caos-body` 选择器、"新浪=GBK"两次假设翻车为证。采集层最易腐的东西(选择器、编码、源存活)都要运行时现场验。
5. **先采全,后降噪**:采集层求全,精筛(相关性/去重)在下游。
6. **技术服务业务**:通用打底先跑起来,核心源观测到问题再单独优化。
7. **同机器不同 host 出网策略可能相反**:直连 vs 代理两套并存。
